Почему токены сжигаются так быстро

Дело не в том, что ты «много пишешь». Claude Code — это не чат. В обычном чате улетает только твоё сообщение. В Claude Code на каждый Enter заново улетает вся история переписки целиком, плюс системный промпт Claude Code, плюс все MCP-серверы, плюс CLAUDE.md, плюс описания всех инструментов.

Это stateless API — без состояния. Представь друга с очень короткой памятью: чтобы поддерживать беседу, каждый раз пересказываешь ему всё с начала. Поэтому 30-е сообщение стоит не как 1-е, а в 10–30 раз дороже. Реальные логи: 1-е сообщение ~15 тыс. токенов, 15-е ~100 тыс., 30-е ~167 тыс. — и срабатывает auto-compact. И всё это при одинаково коротких по смыслу запросах: просто история накапливается, и ты платишь за неё снова и снова.

Что такое токен. Это не слово и не буква, а кусочек текста, на которые модель режет всё, что ты ей даёшь. Примерно 1 токен = 0.75 слова в английском или 0.5 слова в русском; файл на 1000 строк кода — это 8–15 тыс. токенов. Лимит тратится не только на твои сообщения (input), но и на ответы Claude (output), системный промпт Claude Code, твой CLAUDE.md, описания всех инструментов и MCP, и на extended thinking (когда Claude «думает» перед ответом).
Открой /context прямо сейчас. На пустой сессии, до первой буквы, уже занято: системный промпт Claude Code (6–24 тыс.), описания инструментов и MCP (10–80 тыс.), буфер на auto-compact (33–45 тыс.), твой CLAUDE.md. Реальный кейс: 143 тыс. из 200 тыс. заняты до первого сообщения; отключил 3 ненужных MCP — освободилось 38% окна одним движением.

Что в плане (примерно): Pro ~44 тыс. токенов в 5-часовое окно (10–45 сообщений), Max 5× ~88 тыс., Max 20× ~220 тыс. Окно сбрасывается через 5 часов от первого сообщения, не от полуночи. Есть и недельные лимиты — упёрся в них, ждать 5 часов бесполезно. В пик (примерно с обеда до вечера) лимит сгорает быстрее — работать утром выгоднее.

Куда уходят токены — 7 источников

  • 1. Системный промпт Claude Code (14–24 тыс. на сообщение) — плата за вход, не чинится.
  • 2. Раздутый CLAUDE.md — грузится на КАЖДОМ сообщении. 10 тыс. токенов × 30 сообщений = платишь 30 раз. Правило: меньше 200 строк / 2000 токенов.
  • 3. История чата — к 30-му сообщению вся переписка в контексте. Решение: /clear между задачами (по словам Anthropic — самый эффективный рычаг и для качества, и для цены).
  • 4. Read целиком — читает весь файл (800 строк = все 800 в контекст, +70% на нумерацию строк) и держит до конца сессии. Давай точные задачи: не «посмотри логин», а «открой src/auth/login.ts строки 40–80».
  • 5. Куча включённых MCP — каждый добавляет описания инструментов на каждое сообщение (3 MCP ≈ 82 тыс. токенов сверху). Держи включёнными только нужные сейчас — отключай через /mcp.
  • 6. Subagents — multi-agent в 4–7 раз дороже, Agent Teams — в 15 раз. Кейс: Claude сам создал 5 агентов — лимит Pro кончился за 15 минут. Включай осознанно, только под объёмные параллельные задачи.
  • 7. Чинить один баг 10 раз в одном чате — каждая попытка тащит старый код, ошибку и предыдущие попытки (10 циклов ≈ миллион токенов). Попробовал дважды и не работает — /clear и новый промпт с нуля.

9 шагов — что делать

Шаг 1. Диагностика. /context (что занимает окно), /usage (сколько осталось от окна и недели), /cost (сколько сожрала сессия). MCP жрут >5 тыс. — сигнал №1; CLAUDE.md >5 тыс. — сигнал №2.

Шаг 2. /clear между задачами. Самый дешёвый и эффективный шаг. Нюансы: /clear не стирает чекпоинты (вернёшься через /rewind); перед /clear попроси записать состояние в PROGRESS.md; /btw — «боковой» вопрос, не засоряющий сессию.

Шаг 3. Сократи CLAUDE.md. Оставь: команды билда/тестов/линта, нестандартный стиль кода, архитектурные решения, переменные окружения, подводные камни. Удали: всё, что Claude поймёт из кода, стандартные конвенции, «пиши чистый код», описания каждого файла.

Шаг 4. Выключи лишние MCP (/mcp) — держи только нужные сейчас. Приём: CLI вместо MCP где можно (например, gh вместо GitHub MCP — работает через Bash, не грузит системный промпт). Можно ли CLI — спроси у Claude.

Шаг 5. Поставь .claudeignore — как .gitignore, только для контекста. Реальный кейс: стартовый расход упал с 347 тыс. до 19.8 тыс. токенов. Минимум:

# Зависимости
node_modules/
vendor/
.venv/

# Сборка
dist/
build/
.next/
.nuxt/
coverage/

# Логи
*.log
logs/

# Lockfile (часто >20K токенов)
package-lock.json
yarn.lock

# Секреты
.env
.env.*
*.pem

# Большие данные
*.sqlite
data/raw/

Шаг 6. Поставь Sonnet по умолчанию (/model sonnet). Opus — «архитектор», планирует сложное, стоит как ×5 Sonnet; Sonnet закрывает 90% задач; Haiku — мелочь. Сидишь на Opus постоянно на Pro — сожжёшь лимит за пару часов. Переход Opus→Sonnet: −30–40% расхода. Не переключай модель в середине сессии — ломает кэш.

Шаг 7. Plan mode для сложного (/plan) — Claude только читает и думает, потом пишет код. Workflow: Explore → Plan → Implement → Commit. Даёт −50–70% на сложных задачах. Применяй, если задача больше трёх файлов / рефакторинг / незнакомая база. Не нужно для тривиальных правок (правило одного предложения).

Шаг 8. Точечные запросы. Не «проверь логин, там что-то не так», а «открой src/auth/login.ts, функция verifyUser на строке 42 возвращает null вместо ошибки — поправь». Используй @-ссылки: @src/components/Button.tsx, @README.md.

Шаг 9. Не ломай кэш. Claude кэширует системный промпт, CLAUDE.md и историю (cache hit в 10 раз дешевле; 95% токенов — это хиты, за счёт этого Pro и работает). Ломают кэш: смена модели, подключение/отключение MCP или правка CLAUDE.md в середине сессии, перерыв >5 мин (Pro) / >1 ч (Max). Все настройки делай на старте и не меняй до конца.

Главное, что запомнить

Подписка Pro работает только за счёт prompt caching (95% трафика по скидке 90%). Всё, что ломает кэш или раздувает контекст, стреляет тебе в ногу. Главный сдвиг: думать не «сколько сообщений я задал», а «насколько чистый и точный контекст в сессии». Один грязный промпт с чтением 50 файлов = 30 чистых точечных запросов. Дисциплина /clear + /context + точные пути даёт 40–70% экономии.

Где ещё это работает

Те же принципы — везде, где есть LLM, контекст и платный токен. Обычный Claude в браузере: длинные сессии копят историю — начинай новый чат под новую тему. Cursor, Windsurf, Continue: биллинг свой, архитектура та же. API-интеграции: платишь за каждый токен напрямую, без скидок — особенно важно. ChatGPT: те же привычки — точные промпты, чистый контекст, разделение задач между чатами.

Дни бездумного сжигания токенов закончились. Выживают те, кто понимает, что под капотом.
